# Hermes Email Watchdog

> 一个真正替你盯邮箱的私人助理：该打扰时说清楚，不重要时保持安静。

Email Watchdog 以只读方式持续理解新邮件。它不是机械地“总结每封邮件”，而是判断这封信与你有什么关系、现在是否需要行动，以及在你现有的 Hermes 消息渠道里怎样呈现最合适。

## 它会怎样帮你

| 收到的邮件 | Email Watchdog 的处理 |
|---|---|
| 验证码 | 直接突出可复制的验证码和有效期，不堆砌正文 |
| 注册确认 | 提取真正的确认链接和必要说明 |
| 发票或账单 | 提炼金额、编号、截止日，并转发有用附件 |
| 待办与截止日期 | 说明要做什么；你引用推送确认后，才创建提前 24 小时、1 小时的提醒 |
| 安全告警 | 突出账号、设备、地点、风险和建议动作 |
| 普通私人邮件 | 按语境给出自然、简洁的提醒 |
| 需要回复 | 引用推送输入正文，先预览草稿，再确认发送；正文不被模型改写 |
| 营销、满意度邀请、低价值订阅 | 默认静默，但保留可审计记录 |

消息会根据渠道能力灵活使用标题、列表、引用、行内代码与可点击链接。发件人、主题、金额、编号和时间等精确信息会清楚呈现；转发分隔符、邮件头、签名、退订文字、`[image]` 占位符和无意义模板噪声不会被当成“要点”。

## 理解，而不是套模板

插件默认继承 Hermes 当前主模型与回退路由，负责理解邮件事实、意图和行动价值，随后进行独立的发布前审阅，决定：

- 是否值得打扰你；
- 最合适的消息结构；
- 哪些链接和附件真正有用；
- 相对期限在当前时间是否仍有效；
- 是否需要建立日程与提醒。

主模型不可用时由 Hermes 使用其已配置的回退链。你也可以为本插件选择任一已在 Hermes 中配置的模型别名；显式选择的主、备用模型均不可用时，插件会把路由权交还给 Hermes 当前配置，而不是猜测或硬编码其他模型。插件不保存提供方端点或密钥。

邮件中的链接先被登记为只读证据，再由模型按证据编号选择；最终地址始终从原邮件还原，模型不能编造或抄错链接。若所有模型路由都暂时不可用，插件会明确说明已降级，并保全原始发件人、主题、时间、正文摘录、可安全展示的源链接和附件；它不会用模板假装已经理解了邮件。程序层只负责事实来源、安全边界、证据闭合、幂等投递与真实执行结果，不用一堆邮件类型补丁冒充智能。

## 让 Hermes 帮你安装

把仓库链接交给 Hermes，并直接说：

> 帮我安装 Email Watchdog。请检测我已有的邮箱配置，只询问缺失信息，引导我安全接入邮箱；先只读验证和试运行，确认后再启用监控。

Hermes 会主动完成：

1. 检查当前设备是否已有可复用的 Himalaya 邮箱账户；
2. 确认要监控的邮箱、通知目标、提醒与附件偏好；
3. 引导你使用系统密钥环、密码管理器或外部命令提供凭据；
4. 预览变更，原子写入配置；
5. 用“一封信列表”进行只读连接验证；
6. 运行一次真实轮询供你检查；
7. 只有你明确同意后才启用持续监控。

> [!IMPORTANT]
> 不要把邮箱密码、应用专用密码、令牌或密钥发到聊天中。Hermes 应引导你在本机密钥环、密码管理器或环境变量中保存凭据；插件配置只保存取用凭据的命令。

已有账户会自动复用，不会为了升级反复要求登录。配置失败会恢复原状并保持禁用。

## 个性化选项

首次设置会根据你的选择确定：

- 一个或多个邮箱账户；
- 仅行动项通知，或扩大通知范围；
- 主模型和备用模型；
- 是否自动下载并通过当前消息渠道转发安全附件；
- 单个附件大小上限；
- 时区与提醒提前量；
- Hermes 通知渠道与目标。
- 是否启用“草稿确认后回复”，以及每个邮箱的签名档（可选无签名）。

推荐默认值是：仅行动项通知、下载并转发有用的安全附件、单个附件最多 25 MiB；提醒只在用户确认后创建，邮件回复默认关闭。

## 手动管理

通常让 Hermes 操作即可；以下命令用于检查和排障：

```bash
# 从 GitHub 安装并启用插件
hermes plugins install Awenforever/hermes-email-watchdog --enable

# 查看引导状态及尚缺的信息
hermes email-watchdog setup

# 安装或刷新运行时，再做只读体检
hermes email-watchdog install-runtime
hermes email-watchdog himalaya-install --yes
hermes email-watchdog doctor

# 单次轮询，不开启持续监控
hermes email-watchdog run-once
hermes email-watchdog status

# 确认无误后启用；也可随时立即停用
hermes email-watchdog enable
hermes email-watchdog disable

# 卸载运行代码并保留邮箱认证、配置和历史状态，然后移除插件包
hermes email-watchdog uninstall-runtime
hermes plugins remove hermes-email-watchdog
```

Email Watchdog 需要读取环境变量型凭据、调用 Himalaya、通过 Hermes 访问模型并投递消息，因此 Hermes 的社区插件安全扫描可能要求你确认这些能力。请先查看扫描结果；确认仓库来源与权限符合预期后再批准。不要关闭全局安全扫描。首次启用后按 Hermes 提示重启 gateway，再继续 `setup`，已完成步骤不会重复。

`himalaya-install` 不执行远程脚本：它只从 Himalaya 官方 GitHub Release 下载经过本插件验证的 v1.2.0 二进制，核对固定 SHA-256 后安装到当前 Hermes profile 的 `bin/`；不会修改系统软件包或其他 Hermes profile。已有二进制会先备份，失败则保留原版本。

自动化部署仍可使用同一套 plan/apply 内核；详见 [安装与自动化说明](INSTALLATION.md)。自然对话与自动化路径生成相同的标准配置，并共享原子回滚和只读验证。

## 安全边界

- 收信监控严格只读，不提供归档、删除、移动、标记或设为已读操作；
- 邮件回复默认关闭。启用后也只能“引用推送 → 输入正文 → 审阅草稿 → 确认发送”，且默认仅回复发件人；
- `no-reply`、自动通知和高风险地址禁止回复，正文保持原样，仅追加按邮箱配置的签名；
- 邮件中的截止时间不会自动建立提醒；单截止时间需回复 `提醒我`，多截止时间需选择编号；
- 明文密码不会写进插件配置、日志或聊天；
- 危险扩展名、空文件和超限附件不会下载或转发；
- 通知使用持久 outbox，网络失败不会丢消息，也不会阻塞下一轮收信；
- 局部阶段失败会独立记录，不会把已经理解好的内容降级成生硬正文切片。

## 数据、迁移与恢复

配置、已处理索引、缓存、学习数据库、日程、附件、状态和 outbox 位于当前 Hermes profile 的：

```text
plugin-data/hermes-email-watchdog/
```

安装与升级会保留邮箱认证、通知目标、个性化设置和历史状态；已自定义的策略不会被新版默认值覆盖。写入采用锁、临时文件替换与失败回滚。默认卸载只移除插件拥有的运行代码，若运行文件曾被外部修改则拒绝操作；邮箱认证、配置和历史状态均会保留，重装后可无缝继续。

## 运行要求

- Hermes `>=0.21.3,<0.22`
- Python 3.11+
- [Himalaya](https://github.com/pimalaya/himalaya)
- Hermes 中已配置且可用的模型
- 至少一个可用的 Hermes 消息渠道；各渠道适配器与本插件彼此独立
